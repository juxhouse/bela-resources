## Prepare your .NET Project (Other Build Tool)

Prepare these inputs inside the project directory:

- A `.sln` referencing the `.csproj` files to analyse, and their source files.
- Restored NuGet packages and generated sources required by those projects. Analysis runs offline.

A standalone `.csproj` is detected by the action but produces an ECD without the project's code in the current updater. Use a solution.

### Using the GitHub action

Set `build-command` in the project’s `.bela/bela.yml` to your preparation command; it replaces the default preparation and runs from the project directory. For SDK-style projects, your command must leave the packages inside the mounted project, plus each project's `obj/project.assets.json` and generated NuGet `.props`/`.targets`. Package paths in those files must resolve inside the container, where the project is mounted at `/workspace`.

A relative restore path on the runner still creates absolute paths in the metadata. Simply copying packages into `.bela/dependencies` does not fix those paths. One option is restoring with the project mounted at `/workspace`; for example, for `net9.0` (adjust the solution and SDK to your project and updater):

```sh
docker run --rm -v "$PWD:/workspace" -w /workspace \
  mcr.microsoft.com/dotnet/sdk:9.0 \
  dotnet restore Orders.sln --packages /workspace/.bela/dependencies
```

Other tools are valid if they produce the same inputs with accessible paths. The action invokes the analyser directly and performs no additional restore after your command. It creates `.bela` automatically.

### Running the Docker image directly

Create `.bela` with `mkdir -p .bela` and keep the prepared packages in `.bela/dependencies`. Follow the [Docker and upload instructions](/CodeSynchronization.md#2-run-the-bela-updater-docker-app) using the default entrypoint. It copies the workspace and restores offline using `/.bela/dependencies`; existing `obj` files were unnecessary for the validated SDK-style project. The original workspace can be mounted read-only.

A full build, final project assembly and test execution were unnecessary for the validated `net9.0` project. Keep generated sources and other inputs your project actually requires. .NET Framework, `ProjectReference` and source generators remain unvalidated in this suite; see the existing [Framework guidance](/updaters/.NET.md), [.NET results](/reference/custom-build-results/DotNet.md) and [remaining gaps](/reference/custom-build-results/TODO.md).
